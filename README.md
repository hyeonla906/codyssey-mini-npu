# Mini NPU Simulator

Python으로 **MAC(Multiply-Accumulate, 곱하고 누적해서 더하는 계산)**을 직접 구현하여 십자가(Cross)와 X 패턴을 비교하는 콘솔 프로그램입니다. 실제 AI 모델을 학습시키는 프로그램은 아니며, AI 연산의 기초 원리를 숫자 배열과 반복문으로 살펴보는 과제입니다.

> **구현 범위:** 과제 필수 기능만 구현했습니다. 1차원 배열 최적화 및 자동 패턴 생성기 등 선택 보너스 기능은 포함하지 않았습니다.

## 1. 실행 환경과 실행 방법

- **언어:** Python 3.8 이상
- **라이브러리:** Python 표준 라이브러리 `json`, `math`, `time`, `pathlib`만 사용 (추가 설치 불필요)
- **파일 구성:** `main.py`, `data.json`(과제 제공 원본), `README.md`
- **Linux / WSL:** `python3 main.py`
- **Windows:** `py main.py`

```bash
python3 main.py
```

실행 후 메뉴에서 `1`(직접 입력) 또는 `2`(JSON 분석)를 선택합니다. `data.json`은 `main.py`와 같은 폴더에 있어야 합니다. 메뉴 선택이 잘못되면 다시 입력받고, 한 모드를 실행한 뒤 프로그램이 종료됩니다.

```text
=== Mini NPU Simulator ===
1. 사용자 입력 (3×3)
2. data.json 분석
선택:
```

## 2. 프로그램 사용 방법

### 모드 1: 사용자 입력(3×3)

필터 A를 3줄, 필터 B를 3줄 입력한 뒤 저장 내용을 확인하고, 비교할 패턴을 3줄 입력합니다. 각 줄에는 **공백으로 구분한 숫자 3개**를 입력합니다. 줄의 숫자가 3개가 아니거나 숫자로 변환할 수 없으면 안내 문구를 보여 주고 해당 줄을 다시 입력받습니다. `NaN`과 무한대도 입력할 수 없습니다.

**입력 예시 — 필터 A(십자가)**

```text
0 1 0
1 1 1
0 1 0
```

**필터 B(X)와 입력 패턴(같은 숫자를 각각 입력)**

```text
1 0 1
0 1 0
1 0 1
```

**실제 실행 결과 중 주요 부분**

```text
=== MAC 결과 ===
A 점수: 1.0 / B 점수: 5.0
판정: B

=== 성능 분석 (MAC 10회 평균) ===
A 평균 시간: (측정값) ms
B 평균 시간: (측정값) ms
연산 횟수(N², 필터당): 9
```

입력 패턴과 필터의 같은 위치에 있는 숫자를 곱한 값을 모두 더하고, 높은 점수의 필터를 선택합니다. 점수가 같거나 그 차이가 허용오차 미만이면 **`판정 불가`**를 출력합니다. 시간은 실행할 때마다 달라집니다.

### 모드 2: `data.json` 분석

원본 `data.json`에서 5×5, 13×13, 25×25 필터와 패턴들을 불러와 일괄 계산합니다.

- `filters` 아래의 `size_5`, `size_13`, `size_25`에 크기별 `cross`와 `x` 필터가 있습니다.
- `patterns` 아래의 `size_N_idx` 키에는 `input`(2차원 숫자 배열)과 `expected`(예상 정답)가 있습니다.
- 프로그램은 패턴 키에서 `N`을 읽고 `size_N` 필터를 선택합니다.
- `cross`와 `+`는 `Cross`, `x`는 `X`로 통일합니다.
- 패턴과 필터의 크기·숫자 형식·라벨을 검사합니다. 잘못된 개별 케이스는 **FAIL과 이유**를 기록하고 다음 케이스로 넘어갑니다.
- 두 필터의 MAC 점수, 판정, `expected` 및 PASS/FAIL을 출력한 뒤 3×3·5×5·13×13·25×25 성능표와 전체 요약을 출력합니다.

파일 자체를 읽지 못하거나 최상위 `filters`/`patterns` 구조가 잘못된 경우에는 오류를 안내하고 JSON 모드를 종료합니다.

## 3. 주요 구현 기능

| 함수 | 코드에서 담당하는 역할 |
|---|---|
| `mac()` | 두 배열의 같은 위치 값을 곱한 뒤 모두 합산해 MAC 점수를 반환 |
| `input_matrix()` | 3×3 필터·패턴 입력, 숫자 개수 및 형식 검사, 잘못된 줄 재입력 |
| `decide()` | 두 점수의 차이를 `EPSILON`과 비교하여 A/B 또는 Cross/X/UNDECIDED 결정 |
| `measure_mac()` | MAC 함수를 **10회** 호출하고 평균 실행 시간을 ms로 계산 |
| `load_json_data()` | `data.json` 파일 읽기, 최상위 `filters`·`patterns` 자료형 검사 |
| `normalize_label()` | `+`, `cross`, `x`를 `Cross`, `X` 표준 라벨로 변환 |
| `validate_matrix()` | 배열의 N×N 크기, 행·열 개수와 유효한 숫자 검사 |
| `parse_case_key()` | `size_N_idx` 규칙을 검사하고 지원 크기 `N` 추출 |
| `get_filters()` | 해당 크기의 Cross/X 필터 존재 여부, 라벨 중복과 배열 구조 검증 |
| `analyze_case()` | 패턴 한 건 검증 → MAC 점수 계산 → 판정과 `expected` 비교 → 결과·이유 반환 |
| `show_performance()` | 3×3·5×5·13×13·25×25 평균 MAC 시간과 N² 연산 횟수 출력 |
| `mode1()` | 수동 입력부터 저장 확인, 점수·판정 및 3×3 시간 측정까지 실행 |
| `mode2()` | JSON 전체 케이스 검사, 성능표, 전체 테스트·통과·실패 및 실패 목록 출력 |
| `main()` | 실행 메뉴 표시 및 1·2번 모드 선택 |

**MAC 계산 원리:** `pattern[row][col] * filter_data[row][col]`로 같은 위치의 값을 곱하고 `score +=`로 합계를 누적합니다. 외부 계산 라이브러리 없이 두 개의 `for` 반복문으로 직접 계산합니다.

**동점 정책:** `EPSILON = 1e-9`이며 `abs(score_a - score_b) < EPSILON`이면 `UNDECIDED`입니다. 동점이라고 해서 임의로 Cross나 X를 고르지 않습니다.

**성능 측정 방법:** `time.perf_counter()`로 MAC 함수 호출 구간만 재고, 총 소요 시간을 10으로 나눠 1회 평균 시간(ms)을 구합니다. JSON 파싱·콘솔 입력·출력 시간은 측정에 포함하지 않습니다. 모드 2의 3×3 측정에는 고정된 십자가 배열을, 5×5·13×13·25×25 측정에는 검증된 해당 크기의 Cross 필터 배열을 패턴과 필터 양쪽에 사용합니다. **자동 패턴 생성은 하지 않습니다.**

## 4. 결과 리포트

### 4-1. 원본 `data.json` 판정 결과

아래 내용은 현재 `main.py`로 제공된 `data.json`을 실행하여 확인한 결과입니다. 원본 데이터와 허용오차를 수정하지 않았습니다.

| 케이스 | Cross 점수 | X 점수 | 판정 | expected | 결과 |
|---|---:|---:|---|---|---|
| `size_5_1` | 0.9 | 0.8999999999999999 | UNDECIDED | X | FAIL |
| `size_5_2` | 8.9 | 0.1 | Cross | Cross | PASS |
| `size_13_1` | 0.3 | 14.700000000000008 | X | X | PASS |
| `size_13_2` | 7.499999999999997 | 7.5 | UNDECIDED | Cross | FAIL |
| `size_25_1` | 4.9 | 4.899999999999999 | UNDECIDED | X | FAIL |
| `size_25_2` | 52.9 | 0.1 | Cross | Cross | PASS |

**전체 6건 / 통과 3건 / 실패 3건**

실패 목록에 실제 출력되는 사유는 세 케이스 모두 **`점수 차이가 epsilon 미만이라 동점, expected와 불일치`**입니다.

### 4-2. FAIL 원인 진단과 개선 방향

실패가 발생했다고 해서 모두 계산식이 틀렸다고 단정하지 않습니다. 원인을 **데이터/스키마 문제, 로직 문제, 수치 비교 문제**로 나눠 확인합니다.

| 원인 유형 | 확인 방법 | 대응 및 개선 방향 |
|---|---|---|
| 데이터/스키마 문제 | `size_N_idx` 키, `input`·`expected`, 행·열 개수, 필터 라벨 및 숫자 자료형 확인 | 잘못된 항목을 FAIL로 기록하고 이유를 출력한 뒤 다음 케이스 검사 |
| 로직 문제 | 3×3 예제를 손으로 계산한 결과와 `mac()` 점수 비교, 올바른 크기 필터 선택 확인 | `row`·`col` 반복과 누적합 계산 과정을 점검 |
| 수치 비교 문제 | Cross/X 점수 차이와 `EPSILON` 비교, `UNDECIDED` 여부 확인 | 동점 기준을 문서화하고 예상 정답과 결과가 다른 이유 설명 |

**실제 실패한 세 케이스**

| 케이스 | 진단 | 개선·확인 계획 |
|---|---|---|
| `size_5_1` | Cross `0.9`, X `0.8999999999999999`로 거의 같은 점수. 허용오차 때문에 UNDECIDED이며 예상 정답 X와 불일치 | 두 점수 차이를 확인해 동점 판정의 근거를 기록하고, 경계값 테스트로 비교 규칙 검증 |
| `size_13_2` | Cross `7.499999999999997`, X `7.5`로 미세한 차이가 발생. 예상 정답 Cross와 불일치 | 13×13 누적 계산을 재확인하고 부동소수점 차이가 허용오차보다 작은지 점검 |
| `size_25_1` | Cross `4.9`, X `4.899999999999999`로 거의 같은 점수. 예상 정답 X와 불일치 | 25×25에서도 동일한 epsilon 정책이 적용되는지 확인하고 FAIL 이유를 명확히 기록 |

**현재 상태:** 위 세 케이스는 정상적인 숫자 배열로 MAC 계산이 수행되었고, 결과가 `UNDECIDED`로 나와 `expected`와 일치하지 않았습니다. 따라서 현재 확인된 실패 원인은 **수치 비교 정책에 따른 판정 불일치**입니다. PASS 수를 늘리기 위해 제공된 데이터를 변경하거나 epsilon을 임의로 낮추지 않았습니다.

### 4-3. 성능 측정 및 시간 복잡도

아래 평균 시간은 **이번 실행 환경의 측정 예시**입니다. 다른 컴퓨터나 다른 실행 시점에는 값이 달라질 수 있습니다.

| 크기 | 평균 MAC 시간(ms, 실행 예시) | N²(필터 1개당 곱셈 횟수) |
|---|---:|---:|
| 3×3 | 0.001107 | 9 |
| 5×5 | 0.001778 | 25 |
| 13×13 | 0.007748 | 169 |
| 25×25 | 0.027123 | 625 |

**분석 및 해석 (10줄 이상)**

1. MAC 연산은 패턴과 필터의 같은 위치 값을 곱하고 결과를 누적해 하나의 점수로 만듭니다.
2. `mac()` 함수는 바깥 반복문으로 행을 선택하고 안쪽 반복문으로 해당 행의 열을 검사합니다.
3. N×N 배열은 N개 행마다 N개 열을 처리하므로 MAC 한 번에 곱셈을 N²번 수행합니다.
4. 따라서 이 프로그램의 MAC 연산 시간 복잡도는 **O(N²)**입니다.
5. 3×3은 9회, 5×5는 25회, 13×13은 169회, 25×25는 625회의 곱셈이 필요합니다.
6. 25×25의 곱셈 횟수는 5×5보다 25배 많아, 크기가 커질수록 계산량이 빠르게 증가합니다.
7. `measure_mac()`은 각 크기의 MAC 연산을 10회 반복해 총 측정 시간의 평균을 ms로 계산합니다.
8. 성능 측정에는 콘솔 입출력과 JSON 파일 읽기 시간을 넣지 않아 MAC 연산 자체를 비교합니다.
9. 측정값은 실행 환경과 시스템 상태에 따라 달라지므로, 한 번의 측정 시간만으로 절대적인 성능을 단정하지 않습니다.
10. `normalize_label()`은 JSON의 `+`와 `cross`를 `Cross`로 통일해 같은 의미의 라벨을 비교할 수 있게 합니다.
11. `validate_matrix()`와 `get_filters()`는 배열 크기나 자료형이 잘못된 경우 계산 전에 오류를 찾도록 돕습니다.
12. `parse_case_key()`는 패턴 이름에서 크기 N을 추출해 같은 크기의 필터를 선택하는 데 사용합니다.
13. 점수 차이가 `1e-9`보다 작으면 한쪽을 임의로 선택하지 않고 `UNDECIDED`로 처리합니다.
14. 실제 FAIL 3건은 크기·라벨 문제나 확인된 MAC 누적 로직 오류가 아니라, 동점 판정이 예상 정답과 일치하지 않은 경우입니다.
15. 개선 시에는 같은 점수, 허용오차보다 작은 차이, 허용오차 이상의 차이를 각각 시험하여 비교 기준을 더 명확하게 검증할 계획입니다.

## 5. 제출 파일 구조

```text
codyssey-mini-npu/
├── main.py       # 프로그램 실행·MAC 계산·분석
├── data.json     # 제공된 필터와 패턴 데이터(원본 유지)

```

### 확인 방법

```bash
python3 -m py_compile main.py
python3 main.py
```

메뉴 `1`에서는 3×3 입력과 점수·시간을 확인하고, 메뉴 `2`에서는 각 케이스 판정과 총 테스트 수·통과·실패, N² 성능표를 확인합니다.
