# Mini NPU Simulator

Python 콘솔 기반 MAC(Multiply-Accumulate) 패턴 판별 계산기. **필수 기능만 구현**, 외부 라이브러리 미사용.

## 1. 실행 환경

- Python 3.8 이상 / 표준 라이브러리 사용
- 파일 구성: `main.py`, `data.json`(과제 제공 원본), `README.md`
- Linux 실행: `python3 main.py`
- Windows 실행: `py main.py`

## 2. 실행 모드

| 메뉴 | 기능 |
|---|---|
| `1` 사용자 입력 | 필터 A/B와 패턴을 3×3으로 입력 → MAC 점수 → A/B/판정 불가 → 평균 연산 시간 |
| `2` JSON 분석 | 원본 `data.json` 불러오기 → 필터·패턴 검사 → Cross/X 점수 및 PASS/FAIL → 성능표·전체 요약 |

**입력 규칙:** 한 줄에 공백으로 구분한 숫자 3개. 총 3줄 입력. 숫자 개수·형식 오류 시 재입력.

**모드 1 입력 예시**

필터 A:
```text
0 1 0
1 1 1
0 1 0
```
필터 B와 패턴(각각 동일하게 입력):
```text
1 0 1
0 1 0
1 0 1
```
결과: **A 1.0 / B 5.0 / 판정 B**.

## 3. 구현 내용

- `mac()` — 같은 위치의 수를 곱해 누적, MAC 점수 반환
- `input_matrix()` — 3×3 배열 입력과 오류 처리
- `decide()` — 점수 비교 및 epsilon 동점 판정
- `measure_mac()` — MAC 최소 10회 실행, 평균 시간(ms) 계산
- `load_json_data()` — JSON 파일 읽기 및 기본 구조 확인
- `normalize_label()` — `+`, `cross` → `Cross` / `x` → `X`
- `validate_matrix()` — 배열 크기와 숫자 형식 확인
- `parse_case_key()` — `size_N_idx` 키에서 크기 추출
- `get_filters()` — 크기별 Cross/X 필터 검증
- `analyze_case()` — 케이스별 점수 계산, 예상 정답 비교 및 실패 이유
- `show_performance()` — 3·5·13·25 크기별 성능표
- `mode1()`, `mode2()`, `main()` — 실행 모드 및 메뉴 연결

**JSON 구조:** `filters`의 `size_5`, `size_13`, `size_25`에 `cross`·`x` 필터 저장. `patterns`의 `size_N_idx`마다 `input` 배열과 `expected` 정답 저장. 잘못된 케이스는 사유를 출력하고 다음 케이스 계속 처리.

**판정 기준:** `abs(Cross 점수 - X 점수) < 1e-9`이면 `UNDECIDED`. 예상 정답과 일치하면 PASS, 불일치하면 FAIL.

## 4. 결과 리포트

과제 제공 원본 `data.json` 실행 결과.

| 케이스 | Cross 점수 | X 점수 | 판정 | 예상 정답 | 결과 |
|---|---:|---:|---|---|---|
| `size_5_1` | 0.9 | 0.8999999999999999 | UNDECIDED | X | FAIL |
| `size_5_2` | 8.9 | 0.1 | Cross | Cross | PASS |
| `size_13_1` | 0.3 | 14.700000000000008 | X | X | PASS |
| `size_13_2` | 7.499999999999997 | 7.5 | UNDECIDED | Cross | FAIL |
| `size_25_1` | 4.9 | 4.899999999999999 | UNDECIDED | X | FAIL |
| `size_25_2` | 52.9 | 0.1 | Cross | Cross | PASS |

**전체 6건 / PASS 3건 / FAIL 3건**

**실패 목록:**
- `size_5_1` — 점수 차이가 epsilon보다 작아 UNDECIDED, 예상 정답 X와 불일치
- `size_13_2` — 점수 차이가 epsilon보다 작아 UNDECIDED, 예상 정답 Cross와 불일치
- `size_25_1` — 점수 차이가 epsilon보다 작아 UNDECIDED, 예상 정답 X와 불일치

### 성능 분석

MAC 10회 반복 후 1회 평균 시간 측정. 실행 환경에 따라 달라지는 참고값.

| 크기 | 평균 시간(ms, 실행 예시) | N²(필터 1개당 곱셈 횟수) |
|---|---:|---:|
| 3×3 | 0.000913 | 9 |
| 5×5 | 0.002961 | 25 |
| 13×13 | 0.006532 | 169 |
| 25×25 | 0.041417 | 625 |

### 결과 및 원인 분석

1. MAC 계산 — 패턴과 필터의 같은 위치 숫자 곱셈 후 전체 합산.
2. 패턴 크기 — `size_N_idx`에서 N 추출, 해당 크기의 필터 선택.
3. 배열 검사 — 행·열 개수 및 유효한 숫자 여부 확인.
4. 라벨 통일 — `+`와 `cross`는 `Cross`, `x`는 `X`로 정규화.
5. 비교 기준 — Cross 점수와 X 점수의 차이가 `1e-9` 미만이면 동점.
6. 동점 결과 — `UNDECIDED` 출력, 예상 정답이 Cross/X이면 FAIL.
7. `size_5_1` — 0.9와 0.8999999999999999, 동점 처리로 FAIL.
8. `size_13_2` — 7.499999999999997과 7.5, 동점 처리로 FAIL.
9. `size_25_1` — 4.9와 4.899999999999999, 동점 처리로 FAIL.
10. 실패 원인 — 위 세 건은 파일 형식 오류가 아닌 epsilon 판정과 예상 정답의 불일치.
11. 오류 대응 — 파일 읽기·형식 오류 안내, 잘못된 개별 케이스는 실패 사유 출력.
12. 시간 복잡도 — N개 행마다 N개 열 순회 → MAC 1회 곱셈 N²번 → **O(N²)**.
13. 연산량 비교 — 3×3은 9번, 5×5는 25번, 13×13은 169번, 25×25는 625번.
14. 성능 측정 범위 — MAC 호출 시간만 측정; 입력·출력·파일 읽기 시간 제외.
15. 측정값 변동 — CPU 상태와 실행 환경 차이로 평균 시간 변화 가능.
16. 원본 데이터 — FAIL을 PASS로 바꾸기 위한 원본 수정이나 epsilon 변경 없음.
